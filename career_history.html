임종주 | 경력기술서

프로젝트 리딩 · 고객 경험 · 데이터/웹 서비스 기술력
엔씨소프트 CTO 산하 데이터플랫폼실 | 2009.10.19–2024.12.15 (15년 1개월)
프로젝트 포트폴리오 · 웹 이력서 · plutusj@kakao.com

경력 요약

데이터가 발생하는 곳부터 고객이 쓰는 화면까지 연결해 온 개발자이자 프로젝트 리더입니다. MONKEY PM·PL, NOW PL로 운영자·사업부의 문제를 듣고 우선순위와 개발 범위를 정리해 실행을 이끌었습니다. SBoard에서는 전략기획실·경영진이 지표를 빠르게 이해하고 활용할 수 있도록 두 차례 개편을 주도했습니다. 빌링·웹·인게임 로그 수집, DW/DM·ETL, 실시간 집계, Python·Django API와 React·Next.js·TypeScript 화면 개발을 직접 수행했습니다.

차별화된 역량

  • 프로젝트 리딩: 현업 인터뷰와 요구사항 정리, 우선순위·로드맵, 개발 범위 조율, 직접 구현과 후속 인력의 업무 정착.
  • 고객 경험: 경영진의 지표 탐색, 운영자의 장애 대응, 사업부의 실시간 상황 파악처럼 실제 업무 흐름에 맞춰 화면·알림·상호작용을 설계하고 피드백으로 개선.
  • 기술력: 원천 수집·정제·DW/DM·ETL·실시간 처리부터 API·프론트엔드·배포·운영까지 한 서비스의 흐름을 연결.

주요 기술: Python · Java · SQL · Django · React · Next.js · TypeScript · Spark · Kafka · Druid · Informatica · SSIS · Oracle · SQL Server · Hive · Cognos · Tableau

프로젝트 수행 이력

1. OASIS | 데이터 정보 포털

기간·역할: 2010–2016 · 데이터 모델링, ETL, BI 개발·운영

과제. 빌링·웹로그·인게임 로그의 형식과 갱신 주기가 달라 부서별 통계와 KPI를 일관되게 제공해야 했습니다.

  • 현업의 보고서 요구를 데이터 항목과 지표로 풀어 원천 수집·정제 → DW/DM → ETL → Cognos·Tableau 대시보드로 이어지는 흐름을 개발했습니다.
  • Star/Snowflake 모델을 활용한 차원·사실 데이터 구조를 설계하고 Oracle·SQL Server 테이블 및 쿼리를 다뤘습니다. 정기·비정기 적재를 운영하며 품질 확인과 장애 대응을 수행했습니다.
  • 게임에서 사용하던 XML 구조를 활용해 차원 데이터를 자동 갱신하는 기능을 Python·Java로 구현했습니다. 변경되는 게임 항목을 수작업으로 반영하는 운영 부담을 줄이기 위한 작업이었습니다.

결과. 블레이드 앤 소울 론칭 시 데이터 담당자로 참여해 40건 이상의 대시보드·통계 보고서를 기한 내 제공했습니다. 개발 범위는 수집·ETL·모델링·BI까지였습니다.

2. 글로벌 데이터 플랫폼 | NCW·NCT·NCJ

기간·역할: 2010 · 2014 · 2019 · 구축 참여, 데이터 표준화·문서화·교육

과제. 해외 3개 지사의 로그와 운영 환경이 달라도 본사와 지사가 같은 의미의 지표를 조회할 수 있어야 했습니다.

  • 현지 서버·스토리지·DB 요구와 도입 사양을 조사해 구성 및 구축 문서에 반영했습니다.
  • 공통 KPI·로그 기준과 데이터 항목을 정의하고 다국어·타임존·현지 BI 요구를 고려한 DW·ETL 설계에 참여했습니다.
  • 초기 BI 리포트 템플릿과 운영자 교육을 맡았고, NCT 구축 시에는 플랫폼 구축 문서화를 책임졌습니다.

결과. 지사별 데이터를 본사 기준으로 활용할 수 있는 분석·운영 환경 구축에 기여했습니다. 전체 글로벌 아키텍처를 단독 구축한 경력으로 표현하지 않습니다.

3. SBoard | 경영 정보 포털

기간·역할: 2016–2024 · 서비스 기획, 데이터 설계, Django API·React 화면 개발 및 운영

과제. 접속·매출·목표 달성 현황을 경영진이 한 화면에서 빠르게 확인할 수 있도록 데이터 도달부터 렌더링까지 설계해야 했습니다.

  • 전략기획실과 KPI 정의와 화면 이용 흐름을 조율하고, 원천 지표의 표준화·ETL·데이터 모델·API·프론트엔드를 연결했습니다.
  • Python·Django API와 React 대시보드를 직접 개발했습니다. 조회 경로에 ETL 최적화와 캐싱을 적용하고 권한 관리·암호화·보안 감사 대응을 포함해 운영했습니다.
  • 두 차례 대규모 개편을 주도하며 사용자 피드백에 맞춰 지표 체계와 UI/UX를 재정리했습니다.

기술 포인트. 기존 이력서에 기재한 목표/운영 구조는 데이터 도달 1분 단위, 집계 15초, 화면 렌더링 1초입니다. 이 수치는 모든 화면·기간의 보장 성능이 아니라 당시 서비스 설계·운영 설명으로 제시합니다.

4. MONKEY | 장애 모니터링 자동화 플랫폼

기간·역할: 2017–2024 · PM·PL, 메인 개발·운영

과제. 데이터 적재 장애가 메일에 흩어져 있어 운영자가 상태를 빠르게 파악하고 대응하기 어려웠습니다.

  • 운영자 인터뷰로 업무 흐름과 알림의 한계를 파악하고, 적재 품질·장애 상태를 통합하는 모니터링 서비스를 기획했습니다.
  • 관리자 웹·사무실 TV 대시보드와 SMS·이메일 알림을 개발해 상태 확인부터 통지까지 이어지는 운영 흐름을 만들었습니다.
  • PM·메인 개발자로 백엔드·프론트엔드·운영을 맡고, 서비스 확장 시 후속 백엔드·운영 인력의 참여와 업무 이관을 이끌었습니다.

결과. 메일 중심 확인을 공통 대시보드와 알림 중심의 운영 체계로 바꿨습니다. 운영자 피드백을 반영해 반복 업무를 자동화했습니다. 장애 감소율·MTTR 등 미확인 수치는 기재하지 않습니다.

5. NOW | 글로벌 실시간 인게임 모니터링

기간·역할: 2019–2024 · PL, 데이터 설계·메인 개발, UI/UX 기획

과제. 정기 집계로는 게임 운영 중 발생하는 이상 현황을 즉시 확인하기 어려웠습니다. 실시간 로그 처리와 빠른 조회, 현업에 맞는 화면 동선이 함께 필요했습니다.

  • Spark·Kafka 기반 로그 처리와 Druid 저지연 조회 환경 구축에 참여하고, 실시간 데이터 구조 및 파이프라인을 설계했습니다.
  • 사업부 요구를 화면 기능으로 구체화해 다중 필터, 유저 트래킹, 이상 현상 알림, 플레이백을 포함한 대시보드를 설계·구현했습니다.
  • React 기반 초기 화면을 구축하고 Next.js 개편을 리드했습니다. 데이터 처리와 API 조회뿐 아니라 화면 구조·인터랙션·디자인 방향도 직접 다뤘습니다.

결과. 게임 운영 조직이 실시간 데이터에서 이상 현황을 확인하고 대응할 수 있는 서비스를 제공했습니다. Kafka·Spark·Druid 전체 인프라의 단독 구축으로 표현하지 않고, 참여·설계·리딩 범위를 구분합니다.

최근 직접 개발한 서비스

  • PLUTUS 매크로: 금융·경제 지표 수집과 기준일·수집 시각·지연 상태를 표시하는 분석 대시보드.
  • PLUTUS 매매 분석: 조건검색, 종가베팅 후보, 거래대금·수급과 전략 설정을 연결한 웹 서비스.
  • TokenWatch: AI 모델 API 가격·구독료·무료 이용 범위 비교 서비스.
  • AJECT: Next.js·PostgreSQL 기반 회사 웹 서비스 및 문의·알림 흐름, Ubuntu·Nginx·systemd 운영.
  • StarManager (개발 중): 모바일·서버 연동, 일정·미션 중심 자녀 관리 서비스. 출시·사용자 지표는 아직 기재하지 않습니다.

프로젝트 리딩과 고객 경험

MONKEY의 PM·PL, NOW의 PL로 운영자·사업부·전략기획실의 요구와 우선순위를 조율했습니다. 메일 중심 장애 확인을 대시보드·알림 흐름으로 전환하고, 정기 집계에 의존하던 게임 운영 화면을 실시간 탐색과 추적 중심으로 설계했습니다. 해외 플랫폼 구축 문서화와 운영자 교육, 2016–2018년 Hive·SQL 사내 강의로 사용자가 서비스를 활용하도록 도왔습니다. 육군 장교로 2005.11–2008.11 복무하고 중위로 전역했으며, 프로젝트에서는 기술적 결정과 실행·문서화·업무 이관을 맡았습니다.

기업 프로젝트 화면은 보안상 실제 사내 화면 대신 경력 설명용 재구성 시안을 포트폴리오에 게재했습니다. 역할·기간·기술은 기존 이력서 기록에 근거하며, 확인되지 않은 성과 수치는 제외했습니다.
