요약

엔씨소프트 CTO 산하 데이터서비스개발팀과 데이터프로덕트개발팀에서 15년 동안 일했습니다. 운영자, 사업부, 전략기획실, 경영진이 쓰는 데이터 제품을 기획하고 직접 개발해 운영했습니다. MONKEY에서는 PM·PL, NOW에서는 PL을 맡아 사용자 인터뷰, 우선순위 결정, 개발 리딩, 출시 후 개선까지 제품의 전 과정을 책임졌습니다.

퇴사 후에는 금융 데이터 서비스 PLUTUS를 비롯한 제품을 직접 기획하고 개발해 공개·운영하고 있습니다. 사용자가 실제로 쓰는 제품을 처음부터 만들고 운영하는 경험을 쌓고 있습니다.

일하는 방식

문제를 사용자 업무에서 찾습니다

요청받은 기능부터 만들지 않습니다. 운영자가 장애를 어떻게 알아채는지, 경영진이 지표를 어떤 순서로 보는지를 먼저 확인하고 해결할 문제를 정합니다.

기술 비용을 알고 우선순위를 정합니다

수집, 적재, 집계, API, 화면을 모두 직접 만들어 봤습니다. 그래서 기능마다 어느 단계에 얼마의 비용이 드는지 알고 범위와 순서를 결정합니다.

출시 후에도 끝까지 운영합니다

MONKEY, NOW, SBoard 모두 출시 후 수년간 직접 운영했습니다. 사용자 피드백을 받아 기능과 지표 체계를 계속 고쳤습니다.

대표 사례

MONKEY · 장애 모니터링 자동화 플랫폼

PM·PL2017–2024 · 기획, 메인 개발, 운영, 후속 인력 리딩

  • 문제. 데이터 적재 장애 소식이 메일 여러 통에 흩어져 있었습니다. 운영자는 지금 무엇이 문제이고 누가 대응해야 하는지 바로 알기 어려웠습니다.
  • 정의와 결정. 운영자 인터뷰로 확인과 알림 업무를 분석했습니다. 적재 상태, 장애 현황, 알림 순서로 우선순위를 정하고 관리자 웹, 사무실 TV 대시보드, SMS·이메일 알림을 차례로 만들었습니다.
  • 실행. 백엔드, 프론트엔드, 운영을 직접 맡았습니다. 서비스가 커지면서 합류한 개발·운영 인력에게 업무를 나누고 이관했습니다.
  • 결과. 메일로 확인하던 방식을 공통 대시보드와 알림 중심으로 바꿨고, 데이터 조직의 공통 운영 시스템으로 자리 잡았습니다.

NOW · 글로벌 실시간 인게임 모니터링

PL2019–2024 · 데이터 설계, 메인 개발, UI/UX 기획

  • 문제. 정기 집계만으로는 게임 운영 중에 생기는 이상 현상을 바로 확인할 수 없었습니다.
  • 정의와 결정. 사업부가 이상 상황을 발견하고 대응하는 흐름을 분석해 다중 필터, 유저 트래킹, 이상 현상 알림, 플레이백 기능으로 구체화했습니다.
  • 실행. Spark·Kafka 로그 처리와 Druid 저지연 조회 환경 구축에 참여했고, 데이터 구조와 조회 흐름을 설계했습니다. React로 첫 화면을 만들고 Next.js 개편을 이끌며 사용자 피드백을 탐색 동선에 반영했습니다.
  • 결과. 게임 운영 조직이 실시간 데이터로 상황을 파악하고 대응하는 서비스를 제공했습니다.

SBoard · 경영 정보 포털

기획·풀스택2016–2024 · 서비스 기획, 데이터 설계, 개발, 운영

  • 문제. 경영진과 전략기획실이 접속, 매출, 목표 달성 지표를 같은 기준으로 빠르게 확인해야 했습니다.
  • 정의와 결정. 전략기획실과 KPI 정의와 화면 사용 흐름을 함께 정했습니다. 사용자 피드백에 맞춰 두 차례 대규모 개편을 주도하며 지표 체계와 UI를 다시 정리했습니다.
  • 실행. 데이터 모델, ETL, Django API, React 화면을 직접 연결했습니다. 권한 관리, 암호화, 보안 감사 대응까지 포함해 운영했습니다.
  • 결과. 데이터 도달 1분 단위, 집계 15초, 화면 렌더링 1초를 목표로 수집부터 화면까지의 구조를 설계하고 운영했습니다.

직접 만든 제품

회사를 나온 뒤 직접 기획, 개발, 배포, 운영까지 하는 제품을 만들어 공개했습니다.

PLUTUS 매크로 · 금융·경제 지표 대시보드

기획 · 개발 · 운영

금융·경제 지표를 모아 보여 주는 서비스입니다. 지표마다 출처의 갱신 주기와 기준일이 다르다는 점이 핵심 문제였습니다. 지표별로 기준일, 수집 시각, 누락·지연 상태를 함께 표시해 사용자가 데이터가 얼마나 최신인지 판단할 수 있게 했습니다.

PLUTUS 매매 분석 · 시장 데이터 분석 워크스페이스

기획 · 개발 · 운영

조건검색, 종목 분석, 종가베팅 후보, 거래대금·수급 현황, 매매일지를 한 흐름으로 연결했습니다. 시장 데이터를 수집·가공해 실제 분석 순서에 맞게 화면을 구성했고, 로그인 전에 서비스 가치와 무료 이용을 안내하는 소개 페이지를 두었습니다. 자체 MCP·Report API·WordPress를 연결해 AI 도구에서 PLUTUS 리포트로 보고서를 전달하는 흐름도 구현했습니다.

지원 동기

15년 동안 제가 가장 몰입한 일은 모호한 요구를 사용자와 함께 정리하고, 원천 로그부터 화면까지 따라가며 문제의 원인을 찾는 일이었습니다. 이제는 그 경험을 코드를 직접 쓰는 데보다 무엇을 왜 만들지 결정하는 데 더 깊이 쓰고 싶습니다.

PLUTUS를 만들며 금융 제품에서는 데이터가 정확하고 최신이라는 믿음이 사용자 경험의 기본이라는 것을 직접 겪었습니다. 금융을 쉽게 만드는 제품에서, 데이터와 시스템을 깊이 이해하는 PO로서 사용자 문제와 엔지니어링 사이의 결정을 책임지고 싶습니다.
